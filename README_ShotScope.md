# ShotScope: Shot Clusters and Opponent Reach in Badminton

DS-GA 3001, Fall 2026. Team: Ankur Mittal, Ishan Gupta, Pavan Kulkarni.

We study badminton **smashes** with the public ShuttleSet data: does the opponent's reach (how far they must move, and how much time they have) explain whether a smash wins the point, beyond where it landed? The analysis is retrospective (it explains outcomes given where the shot went; it does not predict at hit time). Results are meant to be shown in a D3 interface with the uncertainty behind each number.

## How to run

Set up the environment once (tested with Python 3.9.6 on macOS arm64). Keep the virtual environment outside the project folder if its path contains spaces or an `&`, because those break the launcher scripts inside a venv.

```
python3 -m venv ~/.venvs/shotscope
~/.venvs/shotscope/bin/python -m pip install --upgrade pip
~/.venvs/shotscope/bin/python -m pip install -r requirements.txt
```

`requirements.txt` has the direct dependencies, pinned; `requirements-lock.txt` is the full `pip freeze` of the tested environment. NumPy is pinned below 2 on purpose (see the comment in `requirements.txt`). HDBSCAN is scikit-learn's own, so no separate package is needed. The Shot Influence code needs TensorFlow and will get its own environment.

Then run the EDA:

```
~/.venvs/shotscope/bin/python EDA/eda.py          # run from the repo root, not from inside EDA/
```

To rebuild the cleaned tables and run the checks (from the repo root). `all` and the checks need the ShuttleSet22 files at `ShuttleSet22/set/`; without them, run `shuttleset` only:

```
~/.venvs/shotscope/bin/python cleaning/clean_shuttleset.py all     # or: shuttleset | shuttleset22
~/.venvs/shotscope/bin/python cleaning/build_player_attributes.py
~/.venvs/shotscope/bin/python cleaning/test_clean.py
~/.venvs/shotscope/bin/python EDA/eda_all.py        # the all-matches EDA and the outcome-blind test-set description
~/.venvs/shotscope/bin/python EDA/test_eda.py
```

To merge a different match for the EDA (the output is what `eda.py` reads):

```
python MergedSet/merge.py set <match_folder_name> <output.csv> [1,2]
```

`<match_folder_name>` is a folder name inside `set/`. The optional last argument picks which sets to include (default: set 1). `merge.py` reads its shot-type table from `README.md` in the repo root (see the note at the bottom).

## Data

- **ShuttleSet** (Wang et al., KDD 2023): 44 matches, 104 sets, 36,484 strokes in the files we have, including 2,586 smashes and 1,648 wrist smashes. Source and license: https://github.com/wywyWang/CoachAI-Projects (paper: https://arxiv.org/abs/2306.04948).
- Counts here come from the CSV files. Table 1 of the paper sums to far fewer strokes (about 24.5k), so we do not use it for sample sizes.
- **ShuttleSet22** (Wang et al., 2023, https://arxiv.org/abs/2306.15664): 58 matches, of which 8 are also in ShuttleSet. The other 50 (2022 season, 3,470 smashes) are our **held-out test set**: models are fitted and tuned on ShuttleSet only and scored once on these. The two datasets are cleaned and stored separately and are never mixed. To rebuild the test tables, put the ShuttleSet22 files at `ShuttleSet22/set/` (it is not committed).

## Shot Influence code

`Shot Influence/` is the original authors' implementation of the ICDM 2021 / ACM TIST 2022 papers (MIT license, see `Shot Influence/LICENSE`). We have not modified or run it. Known gaps before it can run on our data:

- It needs a `new_data/dataset.csv` that is not included; we must build it from ShuttleSet, including a choice of "target player" for each rally.
- Its pinned versions (Python 3.6, TensorFlow 2.0) do not install on current machines.
- `evaluate.py` has bugs (for example `load_weight` instead of `load_weights`), and the train/test split is hard-coded.

Details are in Phase 8 of `plan.md`. It is an optional extension; the main project does not depend on it.
